# 台股埋伏股選股器

每個交易日收盤後由 GitHub Actions 自動掃描上市櫃普通股，找出「籌碼沉澱、技術壓縮、業績落底回升、市場冷門」的股票，結果發布在 GitHub Pages。

## 啟用步驟

1. 建立新的 GitHub repo，把整個資料夾推上去。
2. **Settings → Secrets and variables → Actions → New repository secret**：名稱 `FINMIND_TOKEN`，值為你的 FinMind API token。（沒有也能跑，但深入分析檔數會從 100 降到 40。）
3. **Settings → Actions → General → Workflow permissions** 選 *Read and write permissions*（讓工作流程能提交結果）。
4. **Settings → Pages**：Source 選 *Deploy from a branch*，Branch 選 `main`、資料夾 `/docs`。
5. **Actions → screen → Run workflow** 手動跑第一次。建議先在 `limit` 填 `200` 試跑，確認沒問題再跑全市場（約 60–90 分鐘，主要花在 FinMind 節流）。

之後每個交易日台灣時間 18:40 自動執行。結果網址：`https://<帳號>.github.io/<repo>/`；也可以直接看 `docs/results.md` 或每次 Actions 執行的 Summary。

本機執行：`pip install -r requirements.txt && python -m screener.main --limit 100`；測試：`python -m pytest -q`。

## 流程

| 階段 | 範圍 | 資料來源 |
|---|---|---|
| 一、技術面粗篩 | 全市場約 1,800 檔 | yfinance 3 年日K（還原權息） |
| 二、深入分析 | 技術分數前 100 檔 | FinMind 逐檔：融資、法人、月營收、PER/PBR、股權分散 |
| 三、聲量查核 | 總分前 30 檔 | Google News RSS、PTT 股板搜尋 |

## 條件對照：哪些自動化了，哪些做不到

| 你的條件 | 實作方式 | 限制 |
|---|---|---|
| 千張大戶持股↑、股東人數↓ | FinMind `TaiwanStockHoldingSharesPer` 近 8 週；失敗時改用 repo 內每週累積的集保 opendata 快照 | 若你的 FinMind 方案不含此資料集，需累積 4 週以上快照才會開始計分 |
| 融資遞減、創新低 | 融資餘額是否在 120 日低點附近、60 日減幅 | 無融資或融資極少的股票不計分 |
| 特定分點每天穩定吃貨 | **替代指標**：三大法人淨買超占量比與買超天數 ＋ 60 日 Chaikin 資金流（股價不動、收盤卻常在日內高檔） | 證交所分點查詢有圖形驗證碼，不能也不應該自動抓。FinMind 贊助方案有分點資料，把 `use_branch_report` 改成 `true` 即可納入（只查前 15 名） |
| 董監、內部人低檔增持 | 每月抓證交所/櫃買「董監事持股餘額」快照，比較月增減 | 見下方說明；需累積 2 個月才開始計分 |
| 長期橫盤打底 | 找出 120–250 日內振幅 ≤ 40% 且無單邊趨勢（線性迴歸 R² ≤ 0.5）的最長區間 | W 底、圓底、箱型都會被視為「區間整理」，不區分形態 |
| 窒息量 | 20 日均量 ÷ 年均量，以及近 60 日是否出現一年最低 5 日均量 | — |
| 均線多頭排列且糾結 | 5/10/20/60 日線差距 ÷ 收盤價 ≤ 4%，排列順序與 60 日線斜率加分 | 「完全多頭排列」與「高度糾結」本質上互相拉扯，所以排列只占部分分數 |
| 帶量紅K突破 | 收盤突破 60 日高、量 ≥ 2 倍均量、漲 ≥ 3% → 標記「已點火」 | 只標記不計分，避免追高訊號干擾埋伏排序 |
| 產業拐點、過去業績差 | 過去兩年營收年減月份比例、一年前近12月營收衰退幅度、目前虧損 | 只看營收，新產品放量需人工判斷 |
| 隱形冠軍、新供應鏈身份 | `themes.yaml`：你填的代號清單得滿分，產業別命中得部分分數 | **無法自動判斷「市場還不知道」**——這是研究結論，不是資料欄位 |
| YoY 由負轉正 | 最新月 YoY > 0 且前 5 月平均 < 0；連兩月轉正亦高分；MoM 加分 | — |
| 零媒體曝光 | Google 新聞 90 日則數、PTT 股板 90 日篇數 | Dcard、Mobile01 有反爬蟲機制，結果頁提供搜尋連結人工確認 |
| 低本益比 / 淨值比、低基期 | PBR 在 5 年歷史的百分位、PER、股價在 3 年區間的位置 | 虧損股 PER 不計分，改在「業績谷底」加分 |

**關於內部人：** 台灣的「申報轉讓」是董監事要**賣股**前的事前申報，買進不需事前申報，只會反映在每月的持股異動。所以程式看的是董監持股月增減；若同時看到申報轉讓，反而是警訊。

## 計分

12 個訊號各 0–1 分，乘上 `config.yaml` 的 `weights` 加權平均成 0–100 分。資料不足的訊號（例如快照還沒累積夠）不列入分母，並以「資料覆蓋」顯示可用權重比例；覆蓋低於 50% 的股票不上榜。標記「題材未被發現」＝題材命中且媒體聲量低。

## 調參建議

- 入圍太少：放寬 `technical.base.max_range`（0.40→0.50）或 `stage1.max_spread`（0.07→0.10）。
- 窒息量常和流動性衝突：`universe.min_avg_lots` 預設 30 張，想挖更冷門的可調低，但要自己評估進出難度。
- 權重直接改 `weights`，不必加總為 100。

## 已知風險

- 證交所/櫃買 OpenAPI、集保 opendata 的欄位名稱偶有更動；程式用關鍵字比對欄名，失敗時會在結果頁顯示「本次執行的資料限制」，不會中斷整體流程。
- yfinance 在 GitHub Actions 上偶爾被限流，取得率低於 50% 時會顯示警告。
- 公開 repo 若 60 天沒有任何活動，GitHub 會暫停排程；屆時到 Actions 頁面重新啟用即可。
- 本工具只做條件篩選，分數不是報酬預測，不構成投資建議。
